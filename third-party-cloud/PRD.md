# PRD — 第三方云厂商手工机器录入

## 1. 背景与目标

### 1.1 背景

TenSunS-go 当前的云厂商通过账号、任务和同步适配器把 ECS 注册到 Consul。第三方厂商没有可调用 API，运维人员需要在现有云资源编辑入口中手工维护机器的名称、规格、IP 和端口。

已确认的产品决策是复用既有 `/api/edit/cloud`、鉴权、响应 envelope 与 Consul KV / Service 模型；提交完整集合并全量覆盖，缺失项视为删除。不得增加独立第三方 CRUD API 或独立 KV 结构。

### 1.2 目标

在既有云资源编辑模型内支持 vendor 键 **`third_party`**，让登录用户手工维护第三方 ECS 机器，并以现有资源列表可读取的 Consul Service 形式保存结果。

### 1.3 非目标 (Out of Scope)

- 不调用或模拟第三方厂商 API，不保存 AK/SK。
- 不增加 `/api/third-party/*`、独立账户 CRUD、独立 KV 前缀或单条硬删除 API。
- 不创建调度任务、同步记录，不接入 JumpServer。
- 不改变其他云厂商的既有接口或数据。

## 2. 目标用户

| 角色 | 场景 | 痛点 |
|---|---|---|
| 运维管理员 | 登记无 API 的合作方或自建机器 | 无法在统一资源页面维护信息 |
| 值班工程师 | 从资源列表定位手工机器 | 地址、规格和端口分散在系统外 |

## 3. 核心功能 (MVP)

### F1. 既有云资源入口中的第三方厂商

- 现有云厂商选择中可选择“第三方”（`third_party`）。
- `/api/edit/cloud` 的既有返回模型可暴露已有第三方归属；认证与 `code` envelope 不变。

### F2. 全量保存手工机器集合

- 一次提交一个完整机器集合；提交后未出现的旧机器从 Consul Service 中移除。
- 每台机器的名称、规格、IP、端口均必填；IP 支持 IPv4 / IPv6，端口为 1–65535。
- 名称全局不可重复，`IP:端口` 组合全局不可重复；云账号和项目归属为可选。

### F3. 既有资源读取兼容

- 保存后的 Service 使用既有 ECS Service / Meta 形状，使现有资源读取链路可读取。
- 不写入独立第三方 KV；持久化必须采用当前既有 Consul 模型中已确认可用于手工资产的路径。

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 兼容性 | 复用现有 Bearer Token、HTTP 状态和 `code` envelope。 |
| 数据一致性 | 保存以完整集合为单位；成功后 Service 集合与请求一致。 |
| 安全 | 不接收或记录云厂商密钥。 |
| 网络 | IPv4 与 IPv6 均可保存；IPv6 的 `IP:端口` 必须无歧义。 |

## 5. 用户体验流程

1. 用户在既有云资源编辑页选择“第三方”。
2. 用户录入完整机器集合，账号和项目归属按需填写。
3. 前端先校验必填、IP、端口和重复项，再提交至既有写入契约。
4. 后端校验并将当前集合写为既有 Consul Service 模型；旧集合中的缺失项被移除。
5. 用户从现有资源列表读取新集合。

## 6. 成功指标

- [ ] 现有编辑入口可以提交 IPv4、IPv6 的完整第三方机器集合。
- [ ] 缺失必填项、非法 IP / 端口、重复名称、重复 `IP:端口` 返回既有校验失败 envelope。
- [ ] 第二次全量保存会删除缺失机器，且保留机器在现有资源列表可见。
- [ ] `go build ./...`、`go vet ./...`、`go test ./...` 和前端构建通过。

## 7. 风险与依赖

| 风险 | 缓解 |
|---|---|
| 当前 Go 的 `/api/edit/cloud` 只有读语义，`/api/edit/commit` 为占位错误 | 在确定可复用的写端点、请求字段及不触发调度器的既有 KV 映射前，禁止实现。证据见 spec §11。 |
| 当前 Python `edit/commit` 会创建 ECS 调度任务 | 不将其行为直接套用于 `third_party`；需产品确认兼容扩展的确切落点。 |
| IPv6 拼接 `IP:端口` 歧义 | 以 `net.JoinHostPort` 定义 Service address/check/meta 的格式。 |
