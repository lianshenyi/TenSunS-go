# PRD — 第三方手工录入主机

## 1. 背景与目标

### 1.1 背景

TenSunS-go 当前仅能从阿里云、腾讯云、华为云和 AWS 的同步任务读取资源；现场自建机、合作方机器等没有可调用的云厂商 API，无法在同一资源管理界面登记。项目以 Consul 保存资源和服务注册信息，Vue 2 + Element UI 前端通过 Go HTTP API 访问这些数据。

### 1.2 目标

交付一个名为 **“第三方”** 的独立手工资产入口：登录用户可在账户命名空间中新增、查看、编辑、删除机器，并录入名称、规格、IP 和端口；记录会以可查询的 Consul Service 形式保存。

### 1.3 非目标 (Out of Scope)

- 不调用或模拟任何第三方厂商 API，不保存 AK/SK，也不接入现有云账户编辑表单。
- 不创建 `ConsulManager/jobs/*` 定时任务，不触发云同步，不伪造云同步结果。
- 本期不把第三方主机纳入 JumpServer 自动同步；该能力应另行设计并验收。
- 不实现批量导入、批量删除、主机连通性探测、凭据管理或权限分级。

## 2. 目标用户

| 角色 | 场景 | 痛点 |
|---|---|---|
| 运维管理员 | 登记没有开放 API 的合作方或自建主机 | 只能在系统外维护清单，不能统一查看 |
| 值班工程师 | 查找一台手工登记的机器的地址、端口和规格 | 信息来源分散且无法确认最新配置 |

## 3. 核心功能 (MVP)

### F1. 第三方账户命名空间

- 用户可创建名称唯一的第三方账户，用于隔离不同来源的手工主机。
- 账户不能包含机器时才可删除；删除不会隐式删除机器。

### F2. 手工主机 CRUD

- 用户可新增机器的名称、CPU、内存、IP、端口，并可选填系统、分组和状态。
- 用户可查看一个账户的机器列表、修改同一台机器的字段、删除该机器。
- 同一账户中 IP 不可重复；删除后该主机不再是 Consul Service。

### F3. 前后端可联调契约

- Vue 2 + Element UI 页面只使用本需求定义的 `/api/third-party/*` 接口，不依赖尚未实现的旧写接口。
- 所有接口沿用现有 Bearer Token 和 `code` 响应契约，前端能区分成功、校验失败、冲突和认证失败。

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 数据一致性 | 成功的创建/更新同时反映在规范 KV 与 Consul Service；失败不得返回成功码。 |
| 兼容性 | 不改变既有云厂商任务、`/api/edit/*` 或 `/api/nodes/*` 语义。 |
| 安全 | 除登录外全部接口需有效 `Authorization: Bearer <token>`；不接收或记录厂商密钥。 |
| 网络 | IP 支持 IPv4 与 IPv6；Consul TCP health check 使用与保存地址、端口一致的值。 |

## 5. 用户体验流程

1. 管理员在“第三方”入口创建或选择账户。
2. 在该账户填写机器名称、CPU、内存、IP、端口，按需选择操作系统、分组和状态并保存。
3. 页面刷新列表并显示服务地址与规格；编辑仍使用同一 `iid`。
4. 删除前页面提示影响，确认后删除该条机器；账户仍有机器时禁止删除账户。

## 6. 成功指标

- [ ] 可用有效 Token 创建账户、创建一条 IPv4 主机、读取列表、更新端口、删除主机并删除空账户。
- [ ] 无 Token、非法 IP、非法端口、重复 IP 和非空账户删除分别得到定义的失败响应。
- [ ] 成功创建后规范 KV 与 Consul Service 的关键字段可由测试验证。
- [ ] 既有 `go test ./...` 和现有 HTTP 兼容测试持续通过。

## 7. 风险与依赖

| 风险 | 缓解 |
|---|---|
| KV 与 Service 是两个独立 Consul 写入，可能部分失败 | 实现记录失败日志、尽量补偿；接口只在两个写入都成功后返回成功。 |
| 直接写入伪造的云任务会让调度器调用不存在的适配器 | 本契约明确不创建 `jobs` KV，独立 API 读取第三方资产。 |
| 全局 Consul Service ID 冲突 | `iid` 后端生成 `third-` 前缀的 UUID，禁止客户端指定。 |
